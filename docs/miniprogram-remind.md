# 课前 15 分钟提醒（尚未实现）

目标：某一天的计划开始前大约 15 分钟，即使用户已经把小程序划到后台或关掉，微信也会推一条「服务通知」，内容是接下来这节课的名称、时间和地点。

本文只记录做法。代码里还没有订阅消息，也没有定时云函数。

## 为什么不能在小程序里自己计时

小程序进入后台后，页面里的 `setTimeout` 会停，不能靠它在 15 分钟后弹窗。微信也不提供「到点由系统本地通知」的接口。

要用**订阅消息**：用户先点一次「允许」，微信记下这个人还有几次可发额度；云函数按钟点扫描课表，到点调用微信接口把消息送到「服务通知」。

课的时间在云数据库 `families.snapshotJson` 里（含临时改时间、取消）。每个家庭成员的 `openid` 在 `users` 里。这两份数据够用来发提醒，不需要再为课程单独建表。

## 限制（个人主体、工具类目）

- 一般只能用**一次性订阅**，选不到「长期订阅」是正常的。长期订阅只对政务、医疗等公共服务类目开放。
- 用户每点一次「允许」，该模板增加 **1 次**发送额度。一天 3 节课，就要允许 3 次，额度可以攒着。
- 不允许就不会发。不能在进入页面时自动弹授权，必须是用户点击按钮。
- 订阅消息不能拿来做营销。这里只提醒已经排好的课。
- 模拟器和游客模式收不到服务通知。要用自己的 AppID，在真机的开发版、体验版或正式版上测。

## 1. 微信后台

1. 用已绑定云开发的小程序登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)。
2. 「功能」→「订阅消息」→「公共模板库」，选用和上课提醒接近的模板。字段尽量是：课程名称、上课时间、上课地点、备注。
3. 记下模板 ID。写进云函数读取的配置（例如环境变量或云函数目录里的非密钥配置），不要手写进会经常改的页面文案里也没关系，模板 ID 不是密钥。
4. 确认开发环境和正式环境都已开通云函数。定时任务要部署到用户实际连接的那个环境（`.env.development` / `.env.production` 的 `VITE_CLOUD_ENV`）。

怎样算做完：订阅消息列表里能看到选用的模板，并复制到了模板 ID。

## 2. 今天页加「课前提醒」按钮

放在 `apps/miniprogram/src/pages/today/index.vue`，由点击触发：

```ts
uni.requestSubscribeMessage({ tmplIds: ['模板ID'] })
```

- 一次调用里同一个模板 ID 只能出现一次，所以点一次最多加 1 次额度。
- 按钮文案写清楚：「允许一次，提醒接下来的一节课。」
- 用户拒绝时不要反复弹。可以过一会儿再在按钮上提示「还没开启提醒」。

怎样算做完：真机点击按钮会出现微信授权弹窗，点允许后不报错。

## 3. 单独做一个定时云函数 `remind`

不要塞进现有的 `api`。`api` 只在用户打开小程序、调用云函数时运行。提醒要在没人打开时自己跑。

建议目录：`apps/miniprogram/cloudfunctions/remind/`。排课规则继续用 `server/src/domain` 里的 `occurrencesOnDate`，和 `api` 一样由打包脚本打进去，不要在云函数里重写一遍「今天有哪些课」。

`config.json` 里加定时触发器，每 5 分钟一次。微信的 cron 是 7 段：秒 分 时 日 月 周 年。

```json
{
  "triggers": [
    { "name": "tick", "type": "timer", "config": "0 */5 * * * * *" }
  ]
}
```

部署：在微信开发者工具里对 `remind` 选「上传并部署：云端安装依赖」，并确认触发器状态是启用。开发、正式两个环境各部署一次。

怎样算做完：云函数列表里有 `remind`，触发器为启用，日志里能看到每 5 分钟一次的调用。

## 4. 每次触发时做什么

时区用 `Asia/Shanghai`，和现在家庭数据的 `timezone` 一致。

1. 读出 `families`，解析每条 `snapshotJson`。用 `occurrencesOnDate` 算出今天还没取消的课，开始时间以临时调整后的为准（`exception.startTime`，否则用课程的 `recurrence.startTime`）。
2. 只留下开始时间落在「现在之后 13 分钟到 18 分钟」里的课。每 5 分钟扫一次，这个窗口能盖住「提前约 15 分钟」，又不容易漏扫。
3. 用 `users` 里同一 `familyId` 的 `openid` 作为接收人。家长和家人都发，方便接送。
4. 调用：

```js
cloud.openapi.subscribeMessage.send({
  touser: openid,
  templateId: '模板ID',
  page: 'pages/today/index',
  miniprogramState: 'formal',
  lang: 'zh_CN',
  data: {
    // 键名必须和选用模板的字段一致，例如：
    // thing1: { value: 课程名，最多约 20 字，超了要截断 },
    // time2: { value: '2026-10-12 15:00' },
    // thing3: { value: 地点或「地点待定」 },
  },
})
```

`miniprogramState` 要和接收端一致，否则真机没有这条通知：

| 用户打开的版本 | 填什么 |
| --- | --- |
| 开发版 | `developer` |
| 体验版 | `trial` |
| 正式版 | `formal` |

5. 另建集合 `reminders`，文档 ID 用「家庭 ID + 课程 ID + 日期 + 开始时间」。发送前先查，已有记录就跳过，避免同一次扫描或下一个 5 分钟把同一节课再发一遍。发送成功后再写入。这个集合可以在云函数里 `createCollection`，不必在控制台手建。权限建议「所有用户不可读写」。

发送返回 `43101`：这个人没有剩余额度。不要重试。等他再点「课前提醒」并允许之后，才会再有额度。

模板字段超长会直接失败。课程名、地点先截到模板允许的长度（`thing` 类型大约 20 个字）。

怎样算做完：手动云端测试一次，日志里能看到发出去或明确的 `43101`，而不是字段格式错误。

## 5. 用户侧会看到什么

1. 打开小程序，在今天页点「课前提醒」，弹窗里点允许。
2. 之后即使划掉小程序，课前大约 15 分钟，微信「服务通知」会出现这节课的名称、时间和地点。
3. 点通知进入今天页。
4. 没点允许，或额度已经用完，这次不会推。

## 6. 上线前怎么测

1. 真机打开开发版或体验版，点允许。此时 `miniprogramState` 用 `developer` 或 `trial`。
2. 建一节开始时间在 15 分钟后的课。
3. 云开发控制台对 `remind` 选「云端测试」立即跑一次，或等到下一个 5 分钟。
4. 看云函数日志，再看手机微信的「服务通知」。
5. 同一节课再触发一次，确认 `reminders` 挡住了重复发送。
6. 正式版发布前把 `miniprogramState` 改成 `formal`，并部署到正式云环境。

## 7. 费用和以后的收紧

定时触发器按调用次数计费。家庭自用、每 5 分钟一次，一般还在云开发免费额度里。家庭或课程变多之后，再改成只扫描「今天有课」的家庭，避免每次把全部 `snapshotJson` 读出来。
