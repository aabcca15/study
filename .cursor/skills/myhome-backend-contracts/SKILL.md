# 小树成长后端接入契约

当前项目以 `localStorage`（键 `myhome.v1`）模拟持久化。实现或修改业务逻辑时，必须同时维护 [backend-contracts.md](backend-contracts.md)，确保后续后端可以直接按契约接入。

## 开发要求

1. 先确认改动涉及的实体、关联关系和数据所有权。
2. 区分纯界面状态与未来必须由服务端执行的业务逻辑。
3. 涉及服务端逻辑时，在 `backend-contracts.md` 补充：
   - 业务规则与不可破坏的数据约束
   - 建议 API、请求参数、响应和错误码
   - 事务边界、级联删除或共享数据处理方式
   - 权限、并发、幂等和审计要求
   - 从 `myhome.v1` 迁移到服务端的数据映射
4. 前端 Store 方法应保持明确的业务语义，避免把级联规则散落在页面组件。
5. 接入后端后，以服务端结果为准；前端仅做交互确认、请求状态和错误提示。
6. 每次新增相关功能后检查契约是否仍与 `src/domain/types.ts`、`src/stores/app.ts` 一致。

## 当前核心约束

- 至少保留一个孩子。
- 课程可属于一个或多个孩子；共享课程不能因删除其中一个孩子而被误删。
- 排课例外当前按课程生效，共享课程的例外必须继续服务剩余孩子。
- 孩子独享的课程、账单和目标在删除孩子时一并删除。
- 任何级联写操作在后端必须放在同一事务中。
